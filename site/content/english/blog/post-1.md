# 종자 증식실 모니터링 시스템

(참고) AI활용하여 본문 작성함.

## 1. 프로젝트 개요

종자 증식실의 생육 환경을 IoT 센서로 실시간 수집하고, 웹 대시보드에서 시각화하며, 원격으로 제어할 수 있도록 구현한 디지털 트윈 서비스입니다.

- **수행 기간:** 2026.03.11 ~ 2026.06.05
- **수행 환경:** 전북대학교 캡스톤 디자인
- **참여 인원:** 5인 팀
- **진행 상태:** 프로젝트 완료
- **담당 역할:** IoT 센서 데이터 수집, 데이터 파이프라인 구축, 실시간 모니터링 및 원격 제어
- **개인 기여:** IoT·실시간 모니터링 파트를 단독 담당하고 관련 기능의 구현과 통합 검증 수행

## 2. 해결하고자 한 문제와 목표

종자 증식실의 생육 환경을 효과적으로 관리하려면 센서에서 수집한 데이터가 서버와 데이터베이스를 거쳐 웹 화면까지 안정적으로 전달되어야 합니다. 또한 센서 연결이 끊기거나 측정값이 급격하게 변하는 경우 사용자가 이를 빠르게 인지할 수 있어야 합니다.

프로젝트에서는 다음과 같은 문제를 해결하고자 했습니다.

- **통신 환경의 제약:** 특정 공유기에 의존하는 통신 구조에서는 설치 장소가 바뀔 때 센서 연결이 끊길 수 있었습니다.
- **데이터 전달의 신뢰성:** 실제 센서 데이터가 중계기와 서버를 거쳐 데이터베이스까지 정상적으로 전달되는지 검증할 필요가 있었습니다.
- **이상 상황의 인지:** 센서 연결 끊김이나 측정값의 급등·급락을 사용자가 쉽게 확인할 수 있는 모니터링 기능이 필요했습니다.
- **기기 관리의 불편함:** 운영자가 웹에서 단위 코드, 중계기, 센서를 관리할 수 있는 기능이 필요했습니다.

이를 해결하기 위해 센서 데이터 수집부터 데이터베이스 적재, 실시간 시각화, 이상 상태 표시 및 원격 제어까지 연결되는 시스템을 구현하고 실제 기기와 웹 서비스의 연동을 검증하는 것을 목표로 했습니다.

## 3. 담당 역할과 구현 내용

5인 팀 프로젝트에서 IoT·실시간 모니터링 파트를 단독 담당했습니다. 팀의 공동 작업과 구분하여 제가 직접 수행한 주요 작업은 다음과 같습니다.

### 3-1. IoT 센서 데이터 수집 및 전송

- Arduino UNO R4 WiFi 펌웨어를 개발하여 6종 센서의 데이터를 수집했습니다.
- Raspberry Pi 기반 Python 게이트웨이를 구현하고 `paho-mqtt`를 활용해 센서 데이터를 전달하도록 구성했습니다.
- 센서와 중계기 사이의 메시지 규약을 설계했습니다.
- MQTT 인증을 적용한 데이터 전달 구조를 구성하고 실제 센서 데이터의 전달 과정을 검증했습니다.
- CDS 광저항기 분압회로를 설계하고 측정값을 일사량(W/m²)으로 환산하는 기능을 구현했습니다.
- CO₂·온도·습도 데이터의 연관성을 추정하는 모델을 구현했습니다.

### 3-2. 데이터 파이프라인 설계 및 검증

다음과 같은 데이터 전달 흐름을 구성하고 검증했습니다.

`Arduino → Raspberry Pi → MQTT(인증) → Bridge → RabbitMQ → Backend → TimescaleDB`

센서에서 생성한 데이터가 각 구성 요소를 거쳐 데이터베이스에 적재되는지 확인했습니다. 개별 기기의 동작뿐 아니라 실제 센서 데이터가 전체 시스템을 통과하는 과정을 검증했습니다.

### 3-3. 실시간 모니터링 웹 기능

- WebSocket 기반으로 증식실 및 로트별 센서 데이터를 구분해 표시했습니다.
- 데이터 신선도(staleness)를 기준으로 센서의 연결 상태를 판정하는 로직을 구현했습니다.
- 정상·주의·미연결 상태를 대시보드에 표시하도록 구성했습니다.
- 센서 측정값의 급등·급락을 감지하는 로직을 구현했습니다.
- 모니터링 화면의 용어를 통일하고 알림 이력 페이지네이션 등 UI를 정리했습니다.

이를 통해 사용자가 센서 측정값뿐 아니라 연결 상태와 측정값의 변화도 확인할 수 있도록 구현했습니다.

### 3-4. 기기 관리 및 원격 제어

- 단위 코드 관리, 중계기 관리, 센서 관리 CRUD 화면을 구현했습니다.
- Raspberry Pi에서 MQTT 명령을 받아 GPIO를 제어하는 액추에이터 데몬을 구현했습니다.
- 액추에이터 제어 기능을 배포하고 실제 기기와의 통합 동작을 검증했습니다.

### 3-5. 데이터 분석 및 운영 환경 구성

- 실측 농가 데이터를 대상으로 t-test, 시계열 분석, 회귀 분석, 상관관계 분석을 수행하고 보고서를 작성했습니다.
- Raspberry Pi 게이트웨이와 액추에이터 데몬의 실행을 위해 `systemd` 기반 운영 환경을 구성했습니다.
- Docker Compose를 활용한 컨테이너 구성과 Azure VM 배포에 참여했습니다.
- 현장 설치를 위한 통신 설정 매뉴얼을 작성했습니다.
- Raspberry Pi와 백엔드 사이의 통합 검증을 진행해 데이터 전달 과정의 문제를 확인하고 디버깅을 지원했습니다.

## 4. 주요 수행 방법과 선택 이유

### 4-1. 핫스팟 Wi-Fi 기반 통신 환경 구성

**문제:** 특정 공유기에 의존하는 구조에서는 증식실의 설치 장소가 바뀔 때 네트워크 연결을 다시 구성해야 하는 제약이 있었습니다.

**선택한 방법:** 핫스팟 Wi-Fi를 이용해 이동 가능한 통신 환경으로 전환했습니다.

**선택 이유:** 특정 공유기에 대한 의존성을 줄이고 설치 장소가 달라져도 센서와 중계기의 통신 환경을 구성할 수 있도록 하기 위해서였습니다.

**구현 및 결과:** 통신 환경을 변경하고 설정 매뉴얼을 작성했습니다. 이를 통해 현장 설치 시 통신 환경을 구성하는 절차를 정리했습니다.

### 4-2. MQTT와 RabbitMQ를 이용한 데이터 전달

**문제:** 실제 센서 데이터가 여러 구성 요소를 거쳐 데이터베이스까지 정상적으로 전달되는지 확인할 필요가 있었습니다.

**선택한 방법:** MQTT 기반 센서 메시지 전달과 RabbitMQ를 이용한 백엔드 측 메시지 중계 구조를 구성했습니다.

**선택 이유:** 센서와 중계기 사이의 메시지 전달을 구성하고, 서버 측 처리 흐름을 연결하여 전체 데이터 전달 과정을 확인하기 위해서였습니다.

**구현 및 결과:** Arduino에서 수집한 데이터가 Raspberry Pi, MQTT, Bridge, RabbitMQ 및 백엔드를 거쳐 TimescaleDB에 적재되는 것을 확인했습니다.

### 4-3. 데이터 신선도 기반 상태 판정과 WebSocket

**문제:** 센서가 연결되어 있는지, 데이터가 정상적으로 갱신되고 있는지, 측정값이 급격하게 변하는지를 사용자가 쉽게 파악하기 어려웠습니다.

**선택한 방법:** 마지막 데이터 수신 시점을 활용한 신선도 기반 상태 판정과 WebSocket 기반 실시간 데이터 표시를 구현했습니다.

**선택 이유:** 센서의 연결 상태를 단순히 화면에 표시하는 데 그치지 않고, 데이터가 일정 시간 동안 갱신되지 않는 상황을 구분하고 최신 측정값을 웹 화면에 반영하기 위해서였습니다.

**구현 및 결과:** 대시보드에서 정상·주의·미연결 상태를 구분하고 측정값의 급등·급락을 감지할 수 있도록 구성했습니다. 실제 웹 화면에서 센서 데이터가 표시되고 상태 판정이 동작하는 것을 확인했습니다.

## 6. 배운 점과 한계 및 개선 방향

이번 프로젝트는 백엔드와 연동되는 시스템을 처음으로 구현하면서 IoT 기기에서 수집한 데이터가 웹 서비스에 표시되기까지의 전체 흐름을 이해하고 직접 검증한 경험이었습니다.

Arduino와 Raspberry Pi를 이용해 센서 데이터를 수집하고, 메시지 전달 구조를 구성한 뒤 웹 화면에서 데이터가 정상적으로 표시되는지 확인했습니다. 이 과정에서 개별 기기나 화면의 구현뿐 아니라 각 구성 요소 사이의 연결과 데이터 전달을 검증하는 작업이 중요하다는 점을 배웠습니다.

또한 센서의 연결 상태와 데이터의 최신성을 함께 확인하고 실제 기기와 웹 서비스가 연동되는 과정을 점검하면서 IoT 시스템을 통합적인 관점에서 바라보는 경험을 쌓았습니다.

### 한계 및 다음 개선 방향

- 센서별 측정 오차와 보정 상태를 체계적으로 확인할 수 있도록 센서 보정 및 검증 절차를 구체화하고 싶습니다.
- 장기간 운영 시 데이터 누락, 네트워크 단절, 기기 재시작 등의 상황을 반복적으로 시험하여 시스템 안정성을 확인하고 싶습니다.
- 센서 상태 판정 및 급등·급락 감지 기준을 실제 운영 데이터에 맞춰 검토하고 오탐과 미탐을 줄이고 싶습니다.
- 데이터 수집부터 데이터베이스 적재까지의 과정을 추적할 수 있도록 로그와 장애 진단 기능을 보완하고 싶습니다.

## 7. 기술 스택

- **IoT 및 펌웨어:** Arduino UNO R4 WiFi, Raspberry Pi, Python, GPIO, systemd

- **Frontend:** React 18, Vite, Recharts, Axios
- **Backend 및 데이터베이스:** Spring Boot, JPA, PostgreSQL, TimescaleDB
- **데이터 분석:** Python, pandas, t-test, 시계열 분석, 회귀 분석, 상관관계 분석
- **인프라 및 배포:** Docker Compose, Azure VM, Git
